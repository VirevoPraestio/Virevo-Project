# Conversation sequences — index card

The order a consulting conversation is meant to run in, written so progress can
be checked: named steps, their exit conditions, and the test that separates a
conversation going deeper from one going round. Fetch `seq.1` and `seq.2`
together with the overlay for the department in play, on any unscripted
consulting turn. Fetch `seq.7` when a deviation is being worked.

**Group:** cross-department — fetched by conversation stage, not by topic
**Pinned with:** common-elements  **Co-fetches:** the department in play

| id | covers |
|---|---|
| seq.0 | what a sequence is; step as the unit of progress, not stage |
| seq.1 | the canonical ten-stage arc, its steps and their exit conditions |
| seq.2 | telling movement from meandering; the three justified deviations |
| seq.3 | Discharge Process overlay — question areas and the mechanism to name |
| seq.4 | Bed Management overlay — early sizing, the diagnosis beat, bill-to-bill |
| seq.5 | OPD to Diagnostics overlay — derived, scheduling-buffer mechanism |
| seq.6 | Supply Chain overlay — derived, clusters and the misattribution check |
| seq.7 | leaving an open step and coming back; closing one on a gap |
